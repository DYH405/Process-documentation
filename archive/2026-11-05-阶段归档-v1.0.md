## 四、关键证据（已定性）

### 【AMCL 漂移根因】

- init_robot_pose() 无条件 setInitialPose(yaw=0)
- 不重启时第二轮首帧 yaw 108.43° 未回 0，偏差 0.144m / 85~108°
- 重启后第二轮 init 与第一轮差 <1e-6m / <0.001° → 方案 A 有效

### 【单 run 内 AMCL 发散（220630 run）】

- t=340s AMCL 从 (3.839,-3.022) 跳到 (-3.817,2.860)，位移 9.97m
- 落点距 wp3 (-4,3) 约 0.2m → 疑粒子误收敛到结构相似区域，非随机漂移
- 250s 未回正，587 采样中 325 个（55%）|gt-amcl|>1m → 整轮失效
- 该轮“成功”计数不可信，已标 invalid
- 排除：重启失败、坐标系问题、渐进漂移

### 【末点朝向 17~18° 偏差拆分（run1）】

- 指令 90.0°；真值 99.1°（+9.1°）；AMCL 108.0°（+18.0°）
- 真值 0.159 rad < yaw_goal_tolerance 0.25 → Nav2 合法判定到达
- AMCL 多估 ~8.9° → 偏差两源各半
- 位置差仅 0.05m → map 与 world 帧基本对齐

## 五、流程规则（每卡固定生效）

### 【角色】

- 用户：接口人 + 联合执行方，给大方向、原样传递、汇总回传
- 评审方：写任务卡、评审计划与回传、给放行/返工
- agent：与用户联合执行，按卡做事

### 【单卡流程（顺序不可反）】

```
发卡 → agent 回计划 + 拟改片段（≤30行/处，不落盘）→ 评审放行
→ agent 实现 → 回传证据 → 评审通过/返工 → 交接摘要 → 下一卡
```

### 【终端命令规则】

- agent 在 VS Code 插件中终端输出为空
- 所有终端动作由 agent 输出“命令清单”，用户执行后贴回
- 命令清单格式：编号 | 目的 | 命令全文 | 预期输出特征
- 分批 ≤5 条/组；>50 行必须自带 grep/head/tail 收窄
- 用户未贴结果前，禁止写“已通过/已验证”

### 【文档规则】

- 每卡同卡更新文档，不分卡补
- 每卡更新文档头部：实际日期 + 实际阶段
- 回传必须列更新位置；无影响需写理由

### 【代码规则】

- 新增代码逐行中文注释：函数头、关键逻辑、参数用途
- 禁止重构：不重命名参数/变量/函数/文件/话题，不合并拆分搬迁函数，
  不改缩进风格与日志格式
- 计划外改动先报备，不顺手修
